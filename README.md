# GoldTrend Pro

پلتفرم تحلیل بازار، پیش‌بینی و تصمیم‌یار برای **طلای ۱۸ عیار ایران (تومان/گرم)** — بر پایه‌ی هسته‌ی تمیز و تست‌پذیر پروژه‌ی `GoldTrend_Pro` (جمع‌آوری داده، SQLite، منبع‌محوری)، با لایه‌های تحلیل، بک‌تست، Agent و رابط کاربری فارسی.

> ابزار تصمیم‌یار است؛ پیش‌بینی قطعی یا تضمین سود نیست.

## اجرا
```bash
python -m venv .venv && source .venv/bin/activate      # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
python -m app.main init-db
python -m app.main backfill          # دریافت تاریخچه (نیازمند اینترنت)
python -m app.main serve             # http://127.0.0.1:8765
```
| دستور | کار |
|---|---|
| `serve` | رابط کاربری وب (فقط روی 127.0.0.1) |
| `collect` / `backfill` | دریافت قیمت لحظه‌ای / تاریخچه |
| `analyze` / `report` | اجرای تحلیل و چاپ گزارش روزانه |
| `backtest` | اجرای مجدد کامل بک‌تست Walk-Forward |
| `quality` | بررسی کیفیت داده و ثبت پرچم‌ها |
| `python -m tests.run_tests` یا `pytest` | تست‌ها |

بار اول بک‌تست حدود ۱۵ تا ۶۰ ثانیه طول می‌کشد و برای هر «آخرین تاریخ داده» کش می‌شود. UI در این مدت قفل نمی‌شود (کارهای سنگین در Thread پس‌زمینه‌اند).

## یافته‌های مهم درباره‌ی داده
- `raw_json` منابع تاریخی شامل **OHLC واقعی** است (YFINANCE_IR برای طلا/دلار، High/Low برای XAUS). کندل‌ساز قدیمی آن را دور می‌ریخت؛ `panel.py` آن را بازسازی می‌کند. در نتیجه ATR/ADX/Ichimoku برای هر سه دارایی معتبرند. `open` انس موجود نیست و NaN می‌ماند.
- کندل ۴ ساعته‌ی ساختگی تولید نمی‌شود.
- XAU/USD فقط حدود ۵ سال تاریخچه دارد؛ هدف ۱۰ ساله برای انس هنوز تأمین نشده.
- تاریخچه‌ی ایران از `yfinance-ir` (غیررسمی) می‌آید و در بازه‌هایی قیمت تکراری (stale) دارد؛ این موارد با `q_flat_run` ثبت می‌شوند و می‌توانند خودهمبستگی ظاهری ایجاد کنند.
- نقره، مس، آلومینیوم، بیت‌کوین، سکه و مظنه: **بدون منبع داده‌ی معتبر در پروژه‌اند و داده‌ی ساختگی جایگزین نشده**. معماری چنددارایی است؛ با افزودن کلکتور (`app/collectors`) و ثبت نماد در `SEED_SYMBOLS` قابل افزودن‌اند.

## نتایج بک‌تست واقعی (Walk-Forward، آغاز آزمون ۲۰۱۶، فاصله‌ی embargo برابر افق)
| افق | بهترین مدل | RMSE/RW | p (DM) | Ensemble |
|---|---|---|---|---|
| ۱ روز | Ridge | 0.999 | 0.94 | غیرفعال |
| ۳ روز | Ridge | 0.995 | 0.61 | غیرفعال |
| ۵ روز | AR(5) بازگشتی | 0.990 | 0.145 | غیرفعال |
| ۷ روز | AR(5) بازگشتی | 0.981 | 0.012 | غیرفعال |
| ۱۰ روز | AR(5) بازگشتی | 0.968 | 0.0005 | غیرفعال (p=0.135) |

- در افق‌های کوتاه هیچ مدلی از Random Walk بهتر نیست و دقت جهت‌دار مدل‌ها کمتر از «نرخ پایه‌ی صعود» (~۶۰٪) است.
- در ۷ و ۱۰ روز بهبود کوچک ولی معنادار دیده می‌شود (عمدتاً در رژیم‌های روندی؛ در رژیم خنثی تقریباً صفر). این می‌تواند بخشی ناشی از قیمت‌های تکراری منبع باشد.
- شرط فعال‌سازی Ensemble (کاهش ≥۱٪ RMSE و p<۰٫۱) از قبل تعیین شده و پس از دیدن نتایج تغییر نکرده است.
- بازه‌ی ۸۰٪ کالیبره‌شده: پوشش خارج‌نمونه ≈ ۷۹٫۴ تا ۸۰٪.
- امتیاز فنی در تاریخچه همبستگی مثبت و پایدار با بازده ۵ تا ۲۰ روز آینده دارد (ماهیت مومنتومی؛ بخش زیادی از تاریخچه صعودی بوده است).

## قاعده‌ی سیگنال
BUY/SELL فقط وقتی صادر می‌شود که **حداقل دو منبع شواهد اعتبارسنجی‌شده هم‌جهت** باشند، تناقضی نباشد، داده معتبر و نوسان «بالا» نباشد؛ در غیر این صورت HOLD با ذکر دلیل. الگوهای تاریخی توصیفی‌اند و رأی اعتبارسنجی‌شده حساب نمی‌شوند. احتمال موفقیت عددی ارائه نمی‌شود.

## محدودیت‌ها و موارد اختیاری
- **ARIMA/SARIMAX/XGBoost اختیاری‌اند** (با نصب `statsmodels` / `xgboost` فعال می‌شوند؛ در محیط توسعه نصب نبودند و تست نشده‌اند). بدون آن‌ها از AR/Ridge/ElasticNet/Gradient Boosting (scikit-learn) استفاده می‌شود. SARIMAX و GARCH هنوز پیاده‌سازی نشده‌اند.
- حجم معاملات وجود ندارد؛ مؤلفه‌ی Volume حذف و وزن‌ها بازنرمال می‌شوند.
- دریافت زنده‌ی داده (TGJU/XAUS/yfinance) در محیط توسعه (بدون اینترنت) اجرا نشده؛ روی سیستم شما باید با `collect` بررسی شود. داده‌ی لحظه‌ای قدیمی‌تر از ۳ ساعت «کهنه» علامت می‌خورد و به‌عنوان قیمت زنده نمایش داده نمی‌شود.
- LLM اختیاری است (`LLM_API_KEY`, `LLM_BASE_URL`)؛ هر پاسخی که عددی خارج از نتایج موتورها داشته باشد رد می‌شود. مسیر HTTP آن با شبیه‌ساز تست شده، نه با سرویس واقعی.
- قابلیت‌های رابط PySide6 پروژه‌ی قدیمی (A) منتقل نشده‌اند؛ UI جدید وب محلی است.
- هشدارها فقط در UI نمایش داده می‌شوند (ایمیل/پیامک ندارد).
